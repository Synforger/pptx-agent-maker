# Third-Party Notices

This file enumerates the OSS dependencies pptx-live-preview ships against (= direct +
transitive) along with each license. It is normally regenerated by `task gen-notices`
(= `scripts/gen-third-party-notices.py`, which wraps `pip-licenses` for Python and
`license-checker-rseidelsohn` for Node).

## Why it ships in the repo

Registries change license metadata asynchronously, so a snapshot in-tree is the only stable
artefact for downstream review. Anyone reading the repo can confirm what they will be
installing without first running `task setup`.

## Bundled dependencies

**None.** The package declares no runtime dependencies — it is built on the Python standard
library alone (`http.server`, `subprocess`, `threading`, `concurrent.futures`). The only extra
installed for development is `pytest`, which is not shipped to users.

## External tools invoked at runtime

These are **not bundled or redistributed**; the tool shells out to whatever the host has
installed, and each keeps its own license:

| tool | used for | license |
|---|---|---|
| LibreOffice (`soffice`) | pptx → PDF conversion | MPL-2.0 |
| poppler (`pdftoppm`) | PDF → JPEG rasterisation | GPL-2.0 |

## Regeneration

```
task gen-notices
git diff --stat THIRD_PARTY_NOTICES.md
git add THIRD_PARTY_NOTICES.md
git commit -m "chore: refresh THIRD_PARTY_NOTICES"
```

Note: the generator exits non-zero when it collects no rows, because it cannot tell "this
project has no dependencies" apart from "no environment was detected". While the dependency
list stays empty, this file is maintained by hand.

Trigger conditions:
- After every `pip install` / `npm install` that adds a new direct dependency
- Quarterly even when no new deps were added (= transitive deps shift)
- Before every tagged release (= snapshot for the release notes)
