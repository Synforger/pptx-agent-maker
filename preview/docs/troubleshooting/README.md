# Troubleshooting

## よくある症状

### `soffice not found` / `pdftoppm not found` で起動しない

**原因**: LibreOffice か poppler が入っていない (= PATH にも既定の場所にも無い)。
**対処**: [Setup](../setup/) の前提環境を入れる。 macOS なら LibreOffice は `.app` のままで良い。

### 画面が「render error」 になる

**原因**: デッキ自体が壊れているか、 LibreOffice の変換が失敗している。
**対処**: エラー本文に soffice の出力がそのまま出る。 まず同じデッキを手元で
`soffice --headless --convert-to pdf` に通し、 単体で変換できるかを切り分ける。

### 保存したのに更新されない

**原因**: 更新時刻が動いていない (= 別名で書き出した、 別のフォルダを見ている)。
**対処**: 監視しているのは渡したパスそのもの。 ヘッダの再描画ボタンで強制的に描き直せる。
なお、 書き込み途中を掴まないよう更新時刻が落ち着くまで 1 巡回ぶん待つ設計なので、
反映が 1 秒ほど遅れるのは正常。

### 案件の名前に ⚠ が付き、 上に赤い帯が出る

**原因**: その案件の `workspace.toml` を読めなかった (= 帯に理由がそのまま出る)。 読めない案件も
欄から消さずに残し、 デッキは見せたまま、 いつものテンプレート (`specimen`) だけを一覧から外す。
帯の末尾に「restart the preview」 と出ている時は、 常駐が起動した時の道具のまま走っていて、
その後に道具が更新されている (= 新しい欄を書いた案件を、 古い道具が知らない)。
**対処**: 常駐は道具の file (= 道具とプレビューの両方) を 5 秒ごとに見直し、 変わって落ち着いたら
同じ引数で自分を起動し直すので、 「restart the preview」 は道具を更新した後の 10 秒ほどで消える。 消えない
時は手で起動し直す (= macOS なら `launchctl kickstart -k gui/$(id -u)/<service の名前>`)。 出ていなければ、
帯の理由どおりに `workspace.toml` を直す。 直ると帯は次の巡回で消える。

### 頁数が多いデッキで重い

**対処**: `--dpi` を下げる (= 既定 110)。 フォルダモードで多数のデッキを同時に置くと
描画が順番待ちになる (= 同時本数に上限あり)。

## 常駐させる

本ツールは前面プロセスとして動く単純な HTTP サーバなので、 常駐は OS の service 機構に任せる
(= macOS なら launchd の LaunchAgent、 Linux なら systemd の user unit)。 監視したいフォルダと
`--port` を固定で渡し、 標準出力と標準エラーをログファイルに向ける。 リポジトリ内に出す場合、
`logs/` は追跡対象外にしてある。

外部から見たい場合も待ち受けは `127.0.0.1` のままにして、 前段のトンネルやリバースプロキシに
公開範囲を任せる (= 本ツール自体に認証は無い)。

## ログ

常駐時のログは service 定義で指定した出力先に出る。 クライアントが接続を切っただけの
`ConnectionResetError` は正常系として握り潰しているので、 ログに出るものは実際の不具合を指す。
