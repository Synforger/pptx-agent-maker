# pptx-live-preview

> 🇬🇧 English: [README.md](README.md)

> PowerPoint のデッキを保存するたび、ブラウザ側が勝手に描き直すローカルプレビュー。

`.pptx` (またはそれが入ったフォルダ) を渡して、表示された URL を開くだけ。手で編集しても
スクリプトで作り直しても、保存を検知して全頁を描き直しページを更新する。デッキを生成する
パイプラインを回しながら結果を見たいとき、毎回 PowerPoint を開かずに済む。

## 使い方

```bash
# 前提: LibreOffice (soffice) と poppler (pdftoppm) が PATH にあること。
# `task doctor` で toolchain の充足を診断できる。
task setup

.venv/bin/pptx-live-preview path/to/deck.pptx     # 単一デッキ
.venv/bin/pptx-live-preview path/to/deck-folder/  # フォルダ内の全デッキをタブで
```

オプション: `--port` (= 0 で空きポート自動)、 `--dpi` (= 既定 200)、 `--no-open` (= ブラウザを開かない)。

## デッキを見る

画面は「保存のたびに更新される様子を眺める」ためでなく、 デッキを頭から通して読むために作ってある。

- **頁一覧** = 左に縦並び。 クリックで飛び、 スクロールに合わせて現在頁が追う
- **一覧表示** (`g`) = デッキ全体を格子で俯瞰する
- **拡大** (`f`) = 1 頁を画面いっぱいに、 本番と同じ見え方で確認する
- **並べ比較** (`c`) = 2 本のデッキを左右に並べ、 下にそれぞれの頁の帯を敷く。 帯は独立して
  動かせるので、 頁数が違うデッキでも対応する頁同士を突き合わせられる
- **発表者ノート** (`n`) = `.pptx` から直接読んで脇に出す
- **デッキ切替** = 左上のメニュー、 または `Ctrl` + `←` / `→`

キー操作: `←` `→` (= `PgUp` / `PgDn` も可) で頁送り、 `Home` / `End` で端へ、 数字を打って
`Enter` でその頁へ、 `Space` で覆いから戻る、 `?` で一覧。

## 仕組み

LibreOffice がデッキを PDF に変換し、 pdftoppm が各頁を JPEG に焼く (= 読む用の原寸と
頁一覧用の小さい絵の 2 通り)。 LibreOffice のプロファイル (= 設定と環境の下調べの置き場) は
変換ごとに作り直さずキャッシュ配下で使い回す (= 1 本ごとの初期化が消える。
1 つを 2 プロセスで共有できないので同時実行数ぶん用意する)。 ラスタライズは頁範囲を分けて
並列に走らせる (= pdftoppm は放っておくと頁を 1 つずつ順に処理する。 出力はバイト単位で
一致)。

頁の実寸は 16:9 のデッキで 2667 x 1500 px。 Retina で幅 1280px に置いたときの物理 2560px を
満たす大きさで、 110dpi (= 1467px) の頃は引き伸ばしになっていた。 代償は焼く時間が少し延びることと
頁あたりの容量が倍 (= ただし実際に見た頁しか取りに行かない)。 絵は画面に入ってから取りに行く — ブラウザ任せの遅延読み込みは
効かない (= 距離を一番外側のスクロール領域で測るので、 中央だけが動くこの作りでは全頁が
「見えている」 と判定される) ため自前で持つ。 初回の転送は画面に入る頁の分だけになる。 ブラウザ側は Server-Sent Events を購読していて、 新しい描画が
乗ると更新する。 監視は更新時刻を 2 回続けて同じ値で観測してから描くので、 書き込み途中の
デッキを掴むことはない。

焼いた絵はキャッシュ配下の保管庫に、 中身の hash そのものを名前にして貯める。 ここから 2 つが
同時に落ちてくる: 再起動しても焼き直さない (= 大きいデッキが並ぶフォルダでも起動がすぐ終わる)、 画像 URL が中身と 1 対 1 なのでブラウザキャッシュが常に正しい。 デッキのバイトが前回と同じなら描画そのものを飛ばす (= 一番重い
LibreOffice の変換ごと飛ぶので、 中身の変わらない吐き直しは無料)。 保管庫を無視して
焼き直すのは手動の再描画ボタンだけ。

SSE は変化時に即時通知するだけで、 待機中は 20 秒毎の keep-alive 以外の通信をしない。

フォルダモードでは複数デッキを並列に描く (= 1 本あたり CPU 1 コアと数百 MB を使うため
同時本数には上限がある)。 PowerPoint のロックファイル (`~$*.pptx`) だけは除き、 それ以外の
`.pptx` は全部デッキとして扱う。
