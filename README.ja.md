# pptx-agent-maker

> **座標ではなく構造で頁を宣言する**デッキ組み立て基盤。同じ役割の頁が毎週同じ形で出て、
> 頁を書く側 (= 人でもエージェントでも) が版面の外に物を置けない。

## なぜ

同じ骨格から毎週組むデッキは、放っておくと揺れる。同じ形で出るはずの頁が毎回ゼロから書かれ、
レイアウトが少しずつずれ、1 箇所直すたびに「焼いて見る」往復が要る。長く続いた週次デッキを
後から数えると、出てくる形はいつも同じだった ― ある週に丸ごと複製された頁が、数週後には
書き直されて別物になり、そして一度も焼かれていない頁 script が積み上がっていた。

どの頁も EMU の座標を手で書いて図形を置いていた。読む側の不満は「間違っている」ではなく
**「デザインが変わるのめっちゃ嫌い」「新しい構成は認知負荷。型が同じだから週をまたいで比較できる」**だった。

## 何が違うか

**頁は型を選んで、そのフィールドを埋めるだけ。**座標を書く口は manifest にも型の中にも無い。

並びは 1 つしかない ― **題 → 条件の帯 → カード → 本体 → 表 → 読み方 → 結論の帯 → 出所**。
書かなかった帯は取られないだけで、順序は動かない。型が決めるのは**本体に何を置くか**だけで、
7 つある (`figure` / `figures` / `figure_grid` / `flow` / `cards` / `board` / `agenda`)。
カード・表・読み方はどの型にも添えられる。

⚠ **位置に名前を付けて「使ってください」にする形は持たない** ― 前の世代がそれで、名前のある
位置のすぐ横に名前のない値が積み上がった。

そうすると 4 つが**構造で**決まる (= 後から番人で探すのではなく):

- **版面の外に出ない** ― 枠は割ることしかできず、割った枠は必ず親の中に在る
- **兄弟が重ならない** ― 同じ面から切り出しているため
- **同じ宣言は同じ座標** ― 2 度組んでも同じ頁。週をまたいだ揺れが起きない
- **絵は縦横比を保つ** ― 置く口が `fit` 1 つしかない

そして 4 つを組めなくしてある (= どれも規律では守れず、実際に何度も出たもの):

- **図解を 1 つも持たない頁** (= 表と文章だけ)
- **表の空セル** (= 「―」を書く。空欄は充填の取りこぼしと見分けが付かない)
- **下限を割る文字** (= スライド実効 10pt)
- **枠に入らない表** ― PowerPoint は表を縮めず枠を下へ伸ばすので、頁から静かに溢れる。
  占める高さは置く前に分かる

## もう 1 つの決まり: 案件は repo の外

道具はここ。manifest・素材・焼いたデッキは、この repo が指すだけの外の作業場所に置く。
データは commit に入らないので、push にも入らない。

## この repo の中身

```
src/pptx_agent_maker/
├── layout/    版面を割る (= 座標が在るのはここだけ)
├── write/     宣言した頁を file にする
├── deck/      型見本の複製と、過去デッキからの頁の輸入
├── checks/    焼いたものを読み直す検査 (= 1 検査 1 file)
├── review/    人の直しを守り、差分として出す
└── project/   repo の外の案件を指す
templates/     案件を作るときの雛形
preview/       ライブプレビュー (= 履歴ごと取り込み、git subtree)
```

案件は repo の外に作り、道具をそこへ向ける:

```bash
python3 -m pptx_agent_maker init <案件のフォルダ>       # 案件の雛形を外に置く
python3 -m pptx_agent_maker build <案件のフォルダ> w1   # manifest からデッキを組む
python3 -m pptx_agent_maker check <案件のフォルダ> w1   # 焼いたものを読み直して検査
python3 -m pptx_agent_maker preview <案件のフォルダ>    # output/ をブラウザで見る
python3 -m pptx_agent_maker review <案件のフォルダ> w1  # 人が直した所を差分で出す
```

⚠ **repo の中を指す `workspace.toml` は拒む**。素材が無ければ、path を返さずそこで止まる。

**file は種類ではなく役割で束ねる** ― 開く前に、その folder に何が在るか読める形にする。
`preview/` は自分の README・test・Taskfile を持ったままで、更新は `git subtree pull`。
