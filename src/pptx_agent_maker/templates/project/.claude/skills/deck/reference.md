# 参照

## 案件を建てる

```bash
pptx-agent-maker init <案件のフォルダ> --specimen <テンプレート.pptx or それを置いた folder>
```

⚠ **見た目は建てるときに決める** (= あとから `specimen.pptx` を手で置き換えると、
忘れた回だけ顔が変わる)。folder を渡すと `specimen.pptx` と隣の `workspace.toml`
(= 色の表) を一緒に持ってくる。

## manifest

```toml
specimen = "specimen.pptx"     # 予約名。案件の見た目
out = "w1.pptx"                # マニフェストの隣に焼かれる
assets = "w1"                  # 省略すると、この file の名前が素材の folder 名

[[pages]]
kind = "copy"                  # テンプレートの N 頁目を複製して文言を差し替える
page = 1
replace = [["旧", "新"]]

[[pages]]
kind = "import"                # 前のデッキの N 頁目を、手を入れたまま持ってくる
deck = "w0.pptx"
page = 12
pictures = ["a.png", "b.png"]  # 頁の絵を並び順 (= 上の段から、同じ段は左から) で入れ替える
tables = [[["手法", "値"], ["A", "1"]]]  # 表の中身を並び順で入れ替える (= 行と列の数は元と同じ)

[[pages]]
kind = "declare"               # 型で組む
type = "figure"
title = "…"
```

⚠ **`why` は 1 行の覚え書き** (= 200 字、日付を書くと拒まれる)。改訂の履歴は git log が持つ。

## recipe (= `recipes.toml`)

```toml
[recipes.result]                # 名前は英数字・-・_
type = "figures"                # 必須
title = "{method} の結果"        # {穴} は呼ぶ頁の fill で埋める
footer = "採点表から"
```

頁は `kind = "recipe"` / `recipe = "<名前>"` / `fill = { ... }` と、recipe に無いキーだけを書く。
拒まれるもの = recipe が決めたキーの書き換え / 埋め残した穴 / 使わない fill / 無い recipe 名。

上げる: `task promote -- <名前> w1:5 w2:7` (= 2 頁以上、同じ型の `declare` だけ)。

## 会社のテンプレートへ上げる (= `lift`)

```bash
pptx-agent-maker lift <案件> <テンプレートの folder> \
    [--recipe <名前>]... [--page <deck>:<頁>]... \
    [--keep "<そのまま残す文言>"]... [--replace "<案件の語>=<差し替え前提の語>"]...
```

テンプレートの folder = `specimen.pptx` + `workspace.toml` (+ `recipes.toml` + `example.toml`)。頁は
`specimen.pptx` の末尾へ、recipe は `recipes.toml` へ。`init --specimen <folder>` が、在る物を全部配る。
`example.toml` はその見本に合わせた見本の宣言 (= 表紙の置き字を全部差し替え、`stale_words` に当たる文を
載せない)。置かなければ道具付属の物が配られ、置き字や検査の語が違う見本では、建てた直後の 1 本が検査で止まる。
文言は `--keep` / `--replace` で扱った物のほか、全部 `<文言 N>` になる (= recipe の文言も同じ。
型の名前は除く)。拒まれるもの = 当たらない `--replace` / グラフや埋め込み file を持つ頁 /
テンプレートに既に在る recipe 名。

## 型 (= 本体に何を置くか)

| 型 | 要るもの | この型だけが読むもの | 本体 |
|---|---|---|---|
| `figure` | `figure` | `caption` | 絵を 1 枚、縦横比のまま最大で |
| `figures` | `figures` | ― | 絵を横に並べる (= 説明は絵ごとに `["a.png", "説明"]`) |
| `figure_grid` | `figures` | `columns` | 絵を格子に並べる |
| `flow` | `stages` | `align_rows` `direction` | 段を左から右へ、あいだに → (= `direction = "down"` で上から下へ、段の中は横に並んで分岐) |
| `roadmap` | `stages` | `align_rows` | 到達点までの段を矢羽根で左から右へ。各段の下にノード |
| `compose` | `rows` | ― | 本体を段とマスで書く。マスに部品を 1 つ (= 上の型も入る)。図が無くても通る |
| `timeline` | `periods` `lanes` | `phases` `milestones` | 期間を左から右、レーンを上から下。レーンの中に棒と印 |
| `chart` | `chart` | ― | 数字から描くグラフを 1 つ (= 棒・縦棒・折れ線・積み上げ・滝グラフ。PowerPoint で数字を直せる) |
| `cards` | ― | ― | 札だけの頁 (= 図が要らない骨格) |
| `board` | `table` | ― | 表が主役の頁 (= 同上) |
| `agenda` | `buckets` | `highlight` `highlight_tone` `numbers` | 章立て (= 同上。`highlight` = 強調する章の番号。`highlight_tone = "accent"` でその章の箱を地の色で強調し (= 書かなければ `◀ この章` の言葉)、`numbers = "circled"` で番号を丸の数字にする) |

### 箱・棒・矢羽根の見た目 (= どれも同じ 4 つのキー)

カード・flow と道のりのノード・`compose` のカード・線表の棒・道のりの段は、どれも同じ 4 つを同じ意味で読む:

| キー | 意味 | 見た目 |
|---|---|---|
| `tone` | 地の色の役 (= 道具の 6 つか、`[theme.grounds]` の名前) | 地の色。字の色と枠は地から決まる |
| `icon` | 名前の前に置く絵 (= `assets/` の PNG など) | 箱は左上に正方形、棒と矢羽根は名前の前に字の高さで |
| `tentative = true` | 在れば / 内容未定 | 紙の色の地に、灰色の点線の枠と灰色の字 |
| `strong = true` | クリティカルパス、目を集めたい 1 つ | 地はそのままで、本文の色の太い枠 (= 点線と一緒なら太い点線) |

- 線表の棒の `tone` は、書かなければレーンの色。道のりの段の `tone` は、書かなければ薄い地 (= 到達点は濃い地)
- ⚠ **強調は絞る** (= 1 頁に 1 本の道筋か 1 つの箱。全部を強調すると何も目立たない)
- 棒にアイコンを付けると名前の使える幅が減るので、短い棒では名前が隣へ出ることがある。アイコンも入らない短さなら止まる

### `flow` の書き方

```toml
[[pages]]
kind = "declare"
type = "flow"
title = "…"
align_rows = true                                      # 任意。同じ順番のノードを横に揃える
# direction = "down"                                   # 任意。段を上から下へ (= 既定は "right"、左から右)

[[pages.stages]]
name = "Intake"                                        # 段の名前
nodes = [
  ["Triage", "sort by impact"],                        # [見出し, 本文]
  { heading = "No owner", body = "the request waits", tone = "bad" },   # 色の役を付ける書き方
  { heading = "Device", body = "reads the tag", icon = "device.png" },   # アイコンを置く書き方
]
settled = "one queue"                                  # 任意。段の下に置く 1 行
```

- **ノードは 2 通りに書ける** ― `["見出し", "本文"]` か、`{ heading = …, body = …, tone = …, icon = … }`
  (= `body` と `tone` と `icon` は省ける)。**カードも同じ 2 通りで書ける**
- **`icon` は箱の左上に置く絵** (= 素材は図と同じく `assets/` から。文字はその右に寄る)。縦横比は
  保ったまま 1 辺 1.2cm の正方形に収まる。読めるのは PNG / JPEG などの絵で、⚠ **SVG は拒まれる**
  (= 表示する大きさの数倍で PNG に書き出す)。濃い地の箱には明るい色の絵を使う。アイコンは頁の図には
  数えない (= 図の要る頁が、アイコンだけで通ることは無い)
- **`tone` は色の役** ― `box` (= 既定) / `band` / `tint` / `accent` / `good` / `bad`、または案件が
  `[theme.grounds]` で名前を付けた地 (= 下の「見た目」)。色そのものは `[theme.palette]` と `[theme.grounds]` が持つ。⚠ **`good` / `bad` は読み (= 良い / 悪い) を示す物にだけ使う**
  (= 飾りで塗ると、色が意味を持たなくなる)
- **薄い地 (= `box` / `band` / `tint`) の箱は、その地を濃くした色の細い枠を持つ** (= 紙の上で端が
  読める。カードの箱も、線表の棒も同じ)。濃い地の箱に枠は無い。枠の色は地から出るので書かない
- **`direction = "down"` は、段を上から下へ並べる** ― 段の中のノードは**横に並ぶ** (= 1 つなら段の幅
  いっぱい、2 つ以上なら等分。そこが横への分岐になり、次の段が 1 つなら合流)。段の名前は左に立ち、段と段の
  間に `↓` が入る。`settled` はその段のノードの下。収まらなければ止まる (= 段を減らすか 2 頁に分ける)。
  `align_rows` は一緒に書けない (= 横に並ぶノードは、はじめから同じ高さ)
- **`align_rows = true`** は、行が意味を持つ頁のため (= 上から 1 番目は誰、2 番目は誰)。
  行の高さはその行で一番高いノードに揃う。書かなければ、ノードは段ごとに自分の高さで積まれる
- ノードの高さは中の文字が実際に折れる行数で決まる (= 書体ごとに測った字幅で数える)
- **文字の大きさ** ― 段の名前 14pt、ノードの見出し 16pt、**本文と `settled` は 12pt**。10pt は
  出所と絵の下の説明だけに使う (= 頁の中身には使わない)

### `roadmap` の書き方

```toml
[[pages]]
kind = "declare"
type = "roadmap"
title = "…"
align_rows = true                                      # 任意。flow と同じ

[[pages.stages]]
name = "Early Nov | 0.4.0"                             # 矢羽根の中の名前 (= 時期と版)
nodes = [
  ["Core", "reads every input"],                       # flow のノードと同じ書き方
  { heading = "Docs", body = "how to start", tone = "tint", icon = "docs.png" },
]

[[pages.stages]]
name = "Jan | 1.0"
goal = true                                            # 任意。最後の段だけ。到達点として強調する
nodes = [ ["Release", "anyone can install it"] ]
```

- **段は左から右へ矢羽根で並ぶ** ― 最初の段は左が平ら、2 段目からは左が切り欠かれ、前の段の先が
  そこへ入る。向きは矢羽根が示すので、段の間に → は置かない
- **`goal = true` は最後の段だけ** (= ほかの段に書くと拒まれる)。到達点の矢羽根は濃い地で、名前が
  一回り大きい (= 16pt。ほかの段は 14pt)。ほかの段の矢羽根は薄い地に枠
- 段のキーは `name` / `nodes` / `goal` と、見た目の 4 つ (= `tone` / `icon` / `tentative` / `strong`)。
  flow の `settled` は読まない。段は 2 つ以上
- 長い名前は矢羽根の中で折れ、全部の矢羽根がいちばん高い名前に揃う
- 収まらない頁は縮めずに止まる (= ノードを短くするか、段を 2 頁に分ける)

### `compose` の書き方 (= どの型にも無い組み方)

```toml
[[pages]]
kind = "declare"
type = "compose"
title = "目標と、それを支える 2 本の柱"

[[pages.rows]]                                         # 1 段目: 横幅いっぱいに 1 枚
[[pages.rows.cells]]
card = { heading = "目標", body = "…", tone = "accent" }

[[pages.rows]]                                         # 2 段目: 2 枚を横に
[[pages.rows.cells]]
card = { heading = "0.4.0", body = "…", icon = "core.png" }
[[pages.rows.cells]]
weight = 2                                             # 任意。幅の比 (= 既定 1)
[pages.rows.cells.timeline]                            # 型を 1 マスに丸ごと入れる (= その型の書き方のまま)
periods = ["Nov", "Dec", "Jan"]
[[pages.rows.cells.timeline.lanes]]
name = "Core"
bars = [ { from = 0, to = 2, text = "build" } ]
```

- **段は上から下、マスは左から右**。マスの幅は `weight` の比。マスには部品を 1 つだけ置く:
  `card` (= ノードと同じ 2 通りの書き方) / `figure` (+ `caption`) / `table` / `text` (= 本文の色と大きさの文章) /
  `points` / `chart` (= 下の「`chart` の書き方」のまま) / 型 (= `flow` `roadmap` `timeline` `figures` `figure_grid`
  `board` `agenda`)。マスに `rows` を書けば入れ子になる
- **高さ** ― カード・表・文章・要点だけの段は**中身の言葉ぶんの高さ**で、同じ段のカードは一番高い物に揃う。
  絵や型の入った段と、段に `weight` を書いた段は、**残りの高さを `weight` の比で分け合う**。分け合う段に置いた
  カードや文章は自分の高さのまま上に寄る (= 段がそれより低ければ止まる。段の `weight` を増やすか、物を減らす)。
  マスの絵は横幅いっぱいで上に寄り、縦が足りなければ縮む
- 座標は書けない (= 割るだけなので、はみ出しも重なりも起きない)。大きさと色は今までどおり決まっている
- 型をマスに入れた時に読むのは、その型のキーだけ (= カード・表・文章は隣のマスに置く)
- 収まらない頁は、どの段のどのマスかを言って止まる (= 縮めない)
- 図が無くても通る (= カードだけの頁も組める)。⚠ だからといって文章だけの頁を作らない

### `timeline` の書き方

```toml
[[pages]]
kind = "declare"
type = "timeline"
title = "…"
periods = ["Jan", "Feb", "Mar", "Apr", "May", "Jun"]   # 列 = 期間 (左から右)
phases = [                                             # 任意。期間の上に掛ける帯
  { from = 0, to = 3, label = "flexible" },
  { from = 3, to = 6, label = "fixed deadlines" },
]
milestones = [ { at = 5.6, text = "Expo" } ]           # 任意。全レーンを貫く日付

[[pages.lanes]]                                        # レーン = 上から下
name = "Core"
tone = "tint"                                          # 任意。このレーンの棒の色の役
bars = [
  { from = 0, to = 1, text = "1.0 complete" },
  { from = 2.5, to = 3, text = "event (if any)", tentative = true },   # 点線の枠
  { from = 1, to = 2.5, text = "build", strong = true, tone = "accent", icon = "core.png" },   # 見た目の 4 つ
  { from = 3, to = 5, text = "shared work", spans = 2 },   # 任意。このレーンと下のレーンにまたがる
]
marks = [ { at = 1, text = "1.0 release" } ]           # レーンの中の菱形
```

- **位置は期間の番号** ― 0 が最初の期間の頭、`periods` の数が最後の期間の終わり、半期間なら 0.5
- **期間は列ごとに見出しの枠を持つ** (= 表の見出しと同じ地に太字)。列は 1 つおきにごく薄い地で
  塗られ、境に線が立つ (= どの棒がどの期間に掛かるかを、見出しから下へ辿れる)。`phases` の帯は
  その上に、端を期間の枠と揃えて置かれる
- **文字は 12pt か 14pt** ― 頁に収まるなら 14pt、詰まった頁は 12pt (= 1 頁の中では全部同じ大きさ)。
  レーンの名前は 14pt の太字。余った高さは棒の高さに配られ、頁の下に空きを残さない
- ⚠ **`phases` と `milestones` は最初の `[[pages.lanes]]` より上に書く** (= TOML では、
  `[[pages.lanes]]` の下に書いたキーはそのレーンのキーになる。下に書くと拒まれる)
- **レーンの `tone`** は `flow` のノードと同じ語彙 (= `box` / `band` / `tint` / `accent` / `good` / `bad`)。
  書かなければ `box` と `band` の交互。薄い地は 3 つ (= `box` / `band` / `tint`) で、**3 者までを
  色で分けられる**。濃い地 (= `accent` / `good` / `bad`) の上の名前は紙の色になる
- **薄い地の棒は、その地を濃くした色の細い枠を持つ** (= 列の薄い地の上でも棒の端が読める)。
  濃い地の棒に枠は無く、`tentative` の棒は点線の枠のまま
- 同じレーンで時期が重なる棒は、自動で段が分かれる
- **棒は `spans` で下のレーンへまたがれる** (= `spans = 2` はこのレーンと 1 つ下。2 つのレーンに
  分けた仕事の、共通の時期を 1 本で描く)。色は書いたレーンのもの、名前はいつも棒の中。
  ⚠ **またがる棒は、覆うレーンの高さを全部取る** ― その時期 (= 両端を含む) に、覆われるレーンへ
  置いた棒と印は拒まれる。端が接するだけの棒は置ける。覆われるだけのレーンは `bars` を書かなくてよい
- 棒の名前は棒の中。2 行でも収まらない名前は棒の隣へ出る。印の名前も隣 (= 右が先、端では左)
- 文字は全部 pptx の文字 (= PowerPoint で直せる)。棒は名前ごと 1 つの図形
- 収まらない頁は縮めずに止まる (= レーンを減らすか、2 頁に分ける)

### `chart` の書き方 (= 数字から描くグラフ)

```toml
[[pages]]
kind = "declare"
type = "chart"
title = "…"
footer = "出所: …"                                    # データの頁には出所を書く (= 検査 unsourced)

[pages.chart]
kind = "column"                                        # bar / column / line / stacked / waterfall / scatter
categories = ["Q1", "Q2", "Q3", "Q4"]                  # 項目 (= 何の数字か)
series = [                                             # 系列 (= 1 つ以上)
  { name = "売上", values = [12, 15, 21, 18] },         # 値は項目と同じ数
]
highlight = "Q3"                                       # 任意。目立たせる 1 つ (= 系列か項目の名前)
unit = "%"                                             # 任意。数字の後ろに付く字
labels = false                                         # 任意。値の数字を付けない (= 既定は付ける)
callouts = [{ at = "Q3", text = "…" }]                 # 任意。1 点を指す注記 (= 下の「注記」)
```

- **伝えたいことで種類を選ぶ** ― 比べるなら `bar` (= 横棒。項目の名前が長い時) か `column` (= 縦棒)、
  移り変わりなら `line`、内訳なら `stacked` (= 積み上げた縦棒)、増減の積み重ねなら `waterfall` (= 滝グラフ)、
  2 つの量の関係なら `scatter` (= 点。書き方は下の「点のグラフ」)。棒と折れ線を重ねるグラフは無い
- **数字は deck の中に入る** ― PowerPoint でグラフを選んで「データの編集」を開くと、表で数字を直せる
  (= 絵ではないので、形はその場で変わる)
- **数は manifest に書くか、CSV から読む** ― `data = "sales.csv"` (= 素材の folder。1 列目が項目、
  2 列目からが系列、1 行目が系列の名前)。`data` を書いたら `categories` と `series` は書かない
- **目を集めるのは 1 つ** ― `highlight` に書いた 1 つだけが差し色で、ほかは灰。系列が 1 つなら項目の名前、
  2 つ以上なら系列の名前を書く (= 系列と項目に同じ名前が在ると拒まれる)
- `highlight` を書かない時の色 ― 系列が 1 つなら差し色。2 つ以上なら、最初の系列が差し色で、続きは
  濃い灰、薄い灰。**4 つめからの系列は `tone` を自分で書く** (= 見分けられる灰が 2 つまでなので)
- 系列の `tone` は箱と同じ語彙 (= `box` / `band` / `tint` / `accent` / `good` / `bad` か、`[theme.grounds]` の名前)。
  `highlight` と一緒には書けない。薄い地の系列は、箱と同じく地を濃くした色の枠を持つ
- **値の数字は 1 度だけ見せる** ― 棒の外の端 (= 折れ線は点の上、積み上げは段の中) に付き、その時は値の軸を
  出さない。`labels = false` なら数字を付けず、値の軸が出る。目盛りの線はどちらでも引かない
- 数字は、書いた中でいちばん細かい桁に揃えて出る (= `12.5` と `21.25` が在れば全部 2 桁)。3 桁ごとに区切る
- **凡例は系列が 2 つ以上の時だけ**、グラフの下に出る。字の大きさは本文と同じ
- `bar` は最初の項目が上 (= 表と同じ読み順)。値の軸を出す時は、グラフの下に出る

#### 点のグラフ (`kind = "scatter"`)

```toml
[pages.chart]
kind = "scatter"
x = "かけた時間 (h)"                                    # 必須。軸の名前 (= 単位も書く)
y = "満足度"                                            # 必須
series = [
  { name = "A 案", points = [[1, 2.5], [2, 3.5], [3.5, 5]] },   # 点 = [x, y]
  { name = "B 案", points = [[1.5, 1], [4, 2]] },
]
highlight = "A 案"                                      # 任意。目を集める系列
```

- **項目を持たない** ― 系列は点 (= x と y の 1 組) の集まり。`categories` も `values` も書かない
- **軸の名前は必ず書く** (= 軸が何かを言わない散布図は読めない)。軸は 2 本とも出て、目盛りの線は引かない
- 色は、ほかのグラフと同じ決まり (= 最初の系列が差し色で続きは灰、`highlight` か系列の `tone` で変える)。
  凡例は系列が 2 つ以上の時だけ
- CSV から読む時は `data = "points.csv"` ― 1 列目が x、2 列目からが系列の y、1 行目が系列の名前。
  空のマスは「その系列は、この x に点を持たない」
- 点に数字は付かず、注記 (`callouts`) も `unit` / `labels` / `totals` も読まない (= 書くと拒まれる)

#### 注記 (`callouts`)

```toml
[pages.chart]
kind = "column"
categories = ["Q1", "Q2", "Q3", "Q4"]
series = [{ name = "北", values = [12, 15, 21, 18] }, { name = "南", values = [8, 9, 14, 16] }]
callouts = [
  { at = "Q3", series = "北", text = "新製品が出た" },   # どの項目の、どの系列を指して、何と言うか
]
```

- **座標は書かない** ― 書くのは項目の名前 (`at`) と系列の名前 (`series`) と一言 (`text`)。点の位置は道具が計算し、
  言葉をグラフの外に、細い線を点の手前 (= 棒に付いた数字の外) まで置く
- 言葉の場所 ― 縦のグラフ (= `column` / `line` / `stacked` / `waterfall`) は**グラフの上**、指す点の真上。
  `bar` (= 横棒) は**グラフの右**、指す棒と同じ高さ。グラフはそのぶん小さくなる
- 系列が 1 つなら `series` は省ける。**`stacked` と `waterfall` は柱 1 本を指す** (= `series` は書けない。
  どの段の話かは言葉で言う)
- 一言は 1 行。1 つの点に注記は 1 つ。**言葉どうしが重なるなら頁が止まる** (= ずらさない、縮めない。
  言葉を短くするか、注記を減らす)
- 折れ線で下の系列の点を指すと、線が上の系列を横切る
- **注記を持つグラフは、描く範囲と値の軸を道具が決めて書き出す** (= 点の位置を計算するため)。
  ⚠ PowerPoint で数字を大きく直すと、棒が値の軸の端を越えたり、注記が点から外れたりする ―
  数字が変わる時は manifest を直して焼き直す。注記の無いグラフは、今までどおり PowerPoint が決める
- グラフと注記は 1 つのグループにまとめてある (= PowerPoint でグラフを動かしても、注記が付いて来る)

#### 滝グラフ (`kind = "waterfall"`)

```toml
[pages.chart]
kind = "waterfall"
categories = ["前年", "新規", "値上げ", "解約", "今年"]
series = [{ name = "利益", values = [100, 42, 8, -30, 120] }]   # 系列は 1 つ。増えた分は正、減った分は負
totals = ["前年", "今年"]                                       # 合計の項目 (= 地面から立つ棒)
unit = "M"
```

- 書くのは**増減の値だけ**。棒を浮かせる位置は道具が計算する
- `totals` に書いた項目は合計の棒 ― 最初の項目なら出発点の値、途中や最後なら、**そこまでの増減を足した値と
  同じでなければ拒まれる** (= 食い違う数字を載せない)
- 色は意味で決まる (= 増えた分は `good`、減った分は `bad`、合計は差し色)。`highlight` と `tone` は書けない
- ⚠ **1 つの段が 0 をまたぐ滝グラフは描けない** ― 0 で 2 つの段に分けて書く
- PowerPoint の表には、台・増えた分・減った分・合計の 4 列が並ぶ (= 台の列は、棒を浮かせるための透明な系列)

## どの型にも添えられるもの

`cards` / `card_columns` / `table` / `note` / `points`

`card_columns` = カードを何枚ずつ並べるか (= 省略すると全部 1 段)。`figure_grid` の `columns` とは別の数。
カードは flow のノードと同じ 2 通りで書ける (= `["見出し", "本文"]` か `{ heading, body, tone, icon }`)。

### 表のセルの状態の印

表 (= `table`。`board` の表も、`compose` のマスの表も同じ) のセルには、言葉の代わりに印を 1 つ書ける:

```toml
table = [
  ["項目", "進み", "状態"],
  ["設計", { harvey = 4 }, { mark = "ok" }],
  ["試作", { harvey = 2 }, { mark = "partial" }],
  ["評価", { harvey = 0 }, { mark = "ng" }],
]
```

- **`{ harvey = 0〜4 }`** ― 4 分の幾つが済んだか (= ハーベイボール。○ ◔ ◑ ◕ ●)
- **`{ mark = "ok" | "partial" | "ng" }`** ― 良い・半ば・悪い (= ✓ △ ×)
- ⚠ **印の字を直に書かない** (= `"○"` と書くと言葉として扱われ、案件の書体に字形が無ければ別の字になる)。
  印として書いたセルは、字形を持つ書体で置かれる ― 字のままなので PowerPoint で直せる
- 印の大きさと寄せは、ほかのセルと同じ。色は付かない

**値の大小を、セルの地の濃さで見せる** (= 表を読む前に、どこが濃いかが目に入る):

```toml
table = [
  ["地域", "先月", "今月"],
  ["北", { text = "12%", shade = 1 }, { text = "48%", shade = 2 }],
  ["南", { text = "71%", shade = 3 }, { text = "96%", shade = 4 }],
]
```

- **`{ text = "…", shade = 0〜4 }`** ― 地は差し色を 4 分の幾つかに薄めた色 (= 4 が差し色そのもの、0 は
  ふつうのセル)。字は、その地の上で読める方の色 (= 濃い地では紙の色) になる
- **段を決めるのは書く人** ― 何を境に濃くするかは、その表が何を言いたいかで決まる。同じ表の中では
  同じ境で段を振る
- 見出しの行には書けない (= 見出しは差し色の地)。印と濃さを 1 つのセルに一緒には書けない

⚠ **その型が読まないキーは拒まれる** (= 書いたつもりで頁に無い、を作らない)。

⚠ **縮むのは絵だけ**。言葉を持つ物 (= カード・表・文章・要点・目次の一覧と章の箱) は、自分の言葉ぶんの
高さが取れなければ頁が止まる。絵も、高さが足りずに 1.2cm (= アイコンの一辺) より低くなるなら止まる
(= 横に長い絵が幅いっぱいで低いのは構わない)。

## 枠まわり (= どの頁も同じ順)

`kicker` / `title` / `condition` / `conclusion` / `footer` / `replace` / `legend` / `sticker`

`legend = false` は、その頁の凡例を消す (= 下の「意味の名前を付けた地」)。

**`sticker = "暫定"` は、頁の性格を言う札** (= 暫定・イメージ・抜粋)。題の帯の右端に、灰の細枠に灰の字で
1 つ立つ。題はそのぶん狭い幅で折れる (= 札の下へは回り込まない)。1 頁に 1 つ、1〜2 語で書く ―
題が置けなくなるほど長い札は拒まれる。

**題は 2 行まで**。2 行に折れた題は、題の帯が 1 行ぶん伸び、本体はそのぶん下から始まる (= 題が本体に
重ならない。いっぱいまで詰めた頁は、題が折れると止まり得る)。3 行に達した題は検査 `long_title` が知らせる。

**題の色と書体はテンプレートのもの** ― 型の頁は、テンプレートの 1 枚目のレイアウトに乗る。そこに題の枠が
在れば、題はその枠として書かれ、色・書体・太さをテンプレートから継ぐ (= 複製した頁の題と揃う)。位置と
大きさは道具が決める ― 大きさをテンプレートに合わせるなら `[theme.type]` の `title` に書く。題の枠が
無いレイアウト (= 表紙が 1 枚目のテンプレート) では、題は本文の色の太字で書かれる。

**題と札は、レイアウトが印字する物の手前で止まる** (= 隅のロゴ)。題はその幅で折れ、札はロゴの手前に立つ。
書く物は無い ― テンプレートを読んで決まる。

## 見た目 (= `workspace.toml`)

```toml
[theme]
font = "Arial"

[theme.palette]
ink = "3F3F3F"      # 本文
accent = "0092D1"   # 読みを示す色 (= 表の見出しもここ)
band = "EAF0F8"     # 条件の帯
tint = "E8F3EA"     # 3 つめの薄い地 (= box / band と並べて 3 者を分ける。ここでだけ変えられる)
wash = "F3F3F3"     # 線表の列を 1 つおきに塗る地 (= ここでだけ変えられる)
```

⚠ **書体と色は、ふつうは書かない** ― 見た目は `specimen.pptx` から読まれる。ここに書くのは、
テンプレートの配色がツールの色の使い方と合わないときだけ。案件が決められるのは**書体・色・文字の大きさ**
(= 下の「資料の使い方」) で、余白と間隔はツールが持つ。

### 資料の使い方と文字の大きさ (= `[theme] use` と `[theme.type]`)

```toml
[theme]
use = "present"        # "read" (= 既定。手元で読ませる資料) か "present" (= 映して話す資料)

[theme.type]           # 任意。役ごとの上書き (= pt)
body = 20
```

**題の上の小さい字の置き場** (= `kicker`) も案件が決める:

```toml
[theme]
kicker = "beside"      # "above" (= 既定。題の上に小さく) か "beside" (= 題の左に同じ行で、差し色の太字)
```

`beside` は題と同じ大きさで題の 1 行目に並び、題はそのぶん狭い幅で折れる (= 番号と 1〜2 語で書く。題が
置けなくなるほど長ければ拒まれる)。帯の高さは `above` の時と同じ。資料全体の見た目なので、頁ごとには
変えられない。

文字の大きさは**資料の使い方**から決まる。映す資料は離れた席から読むので全部が大きく、**載る量はそのぶん減る**
(= 要点だけを載せる)。この file の他の節に書いてある大きさ (= 12pt / 14pt / 16pt …) は `read` のもの。

| 役 | どこに使うか | `read` | `present` |
|---|---|---|---|
| `title` | 題 | 24 | 32 |
| `heading` | カード・ノードの見出し、条件と結論の帯 | 16 | 24 |
| `stage` | 段の名前、レーンの名前、道のりの矢羽根 | 14 | 20 |
| `body` | 本文、表、要点、読み方 | 12 | 18 |
| `caption` | 出所、絵の下の説明、題の上の小さい字 | 10 | 14 |
| (線表の字) | `stage` と `body` の 2 つ (= 収まる大きい方) | 14 か 12 | 20 か 18 |
| (段の間の →) | 使い方が決める | 28 | 36 |
| **下限** | これより小さい字は置けない | 10 | 14 |

- **`[theme.type]` で上書きできるのは上の 5 つの役** (= `title` / `heading` / `stage` / `body` / `caption`)。
  下限より小さい値は拒まれる。決める所は案件のこの 1 か所で、頁ごと・箱ごとには変えられない
- 題の帯・条件と結論の帯・出所の帯の高さは、そこに置く字の大きさに付いて行く。余白と間隔は動かない
- ⚠ **`read` で収まっていた頁が `present` で収まるとは限らない** ― 収まらない頁は縮めずに止まる
  (= 中身を減らすか、2 頁に分ける)。題も 1 行に入る字数が減る (= 全角で 36 字 → 27 字)
- **検査の文字の下限も使い方に揃う** (= `present` は 14pt)。`read` の大きさで作った頁を複製・輸入すると
  当たる。案件で下げるなら `[checks] type_floor = 10`

### 意味の名前を付けた地 (= `[theme.grounds]`)

色で担当や状態を分ける案件は、地の色に**意味の名前**を付けて宣言する:

```toml
[theme.grounds]
"内部向け" = "EAF0F8"     # 日本語の名前は引用符で囲む (= TOML の決まり)
"外部向け" = "FFF4E5"
"共通" = "E8F3EA"
"遅れ" = "8B1E3F"
```

- 頁では `tone = "内部向け"` と書く (= カード・ノード・レーン・`compose` のカード、どこでも)。道具の色の役
  (= `box` / `band` / `tint` / `accent` / `good` / `bad`) もそのまま書ける。同じ名前は宣言できない
- **字の色は地から決まる** ― 本文の色と紙の色のうち、地との差がはっきりする方 (= 濃い地なら紙の色)。
  本文の色の字が乗る薄い地には、地を濃くした色の枠が付く
- **凡例は自動で出る** ― 宣言した名前を使った頁には、本体の真下 (= 表と読み方の上) に色見本と名前が並ぶ。
  並びは宣言の順で、どの頁でも同じ。使っていない名前は出ない。消すのはその頁に `legend = false`
- ⚠ **同じ担当は全部の頁で同じ名前で書く** (= 色を頁ごとに選ばない。色は宣言の 1 か所で決まる)
- 使える名前は `task types` の `tone` の行に出る

## 検査

`build` は最後に 9 つを回す。当たりが 1 つでも在れば `build` は失敗で終わる。

焼いた deck を読み直す検査 (= `check` でも回る):
頁の外 / **重なり** / 文字の下限 / 表の空セル / 内部 file 名 / テンプレートの語の残り /
種類の登録が無い部品 (= 開けない pptx の種) / **題が 3 行以上** (`long_title`、複製・輸入の頁)

manifest を読む検査 (= `build` だけが回す):
**題が 3 行以上** (`long_title`、宣言で組む頁) / **出所の無いデータの頁** (`unsourced`)

- `long_title` ― 題は 2 行まで。3 行に達した題を知らせる (= 短く言い直す)
- `unsourced` ― 宣言で組む頁が絵・表・グラフを持つのに `footer` が空なら知らせる (= どこから来たかを `footer` に
  書く)。流れ図・道のり・線表とカードだけの頁は対象外

`stale_words` は案件の `workspace.toml` に書く。新しい 2 つは案件ごとに外せ、文字の下限は案件で決められる:

```toml
[checks]
stale_words = ["案件名", "第 N 回"]
unsourced = false       # 出所の検査を外す (= 絵が図解ばかりで、出所を書く物が無い案件)
long_title = false      # 題の長さの検査を外す
type_floor = 10         # 文字の下限 (= 書かなければ資料の使い方の下限。read は 10、present は 14)
```

## 題を順に読む

```bash
task titles -- w1
```

頁の番号と題 (= 題の上の小さい字が在ればそれも) を 1 行ずつ出す。**題だけを順に読んで話が通るか**を
見るための口 ― 頁を 1 枚ずつ直していると、並びとしての話は見えなくなる。宣言で組む頁は manifest から、
複製・輸入の頁は焼いた deck から読む (= 先に `build` しておく)。
