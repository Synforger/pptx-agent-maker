# 資料の作法 (= 頁を設計する前に読む)

型と検査が守れるのは、座標と形まで。**何をどの順で言うか、何を載せないか**は、書く人が決める。
ここに在るのは、実際の資料で差し戻された点を畳んだ物 ― 一般的な構成術 (= 結論から言う、漏れなく
重ならず) は前提として省く。機構 (= 型のキー、コマンド) は `SKILL.md` と `reference.md` が持つ。

## 構成 (= 何をどの順で言うか)

- **全体 → 部分** ― まず全体像を 1 頁で見せ、次の頁から、入力の順に 1 段ずつ説明する
- **題を頭から順に読むだけで、話の筋が追える** ― `task titles -- <manifest>` が題を頁の順に出す。
  追えなければ、頁の出来より先に構成が壊れている
- **1 頁 1 メッセージ、題は結論の文** ― 「結果」でなく「売上は伸びたが利益は減った」。言いたいことが
  2 つなら頁を 2 枚にする。題は 2 行まで (= 3 行で検査 `long_title` が知らせる)
- **頁に残すのは、題の証明に要る物だけ** ― 文が言う概念は、図のどこかを指せること (= 図は説明と 1:1)。
  噛み合わない頁は、図か話のどちらかが違う
- **提案は、分かっている制約から始める** ― 制約、取り得る案、案どうしの比べ、勧める案、の順に並べる。
  勧める案の進め方から入ると、なぜその案なのかが読み手に無い
- **結果が 3 頁を超えて続くなら、その読み方を言う頁を 1 枚挟む**
- **1 頁は 1 つの実験で組む** ― 条件を 1 つだけ変えた比較は、その 1 つで頁を作る。2 つの変更を同じ表に
  混ぜると、どちらの効果か読めない。ほかの実験で得た数を、その頁に持ち込まない
- **決めたこと・対応・比較は、表で全量** ― 文章や帯で流さず、行 × 列で出す
- **進捗の報告は「大きなやり遂げ」の単位で抽象する** (= 作業の列挙にしない)
- **目次に、実頁の無い小項目を書かない** (= 残すと、次の回がそれを持ち越す)
- **どの頁でも、読み手が今どこに居るかを題の帯で分かるようにする** ― 題の上の小さい字 (= `kicker`) に、
  章と節の番号・節の名前・節の中の位置を書く (= `3-2 売上の分析 | ② 地域別`)。目次の小項目にも同じ番号を
  付け、頁と目次を番号で行き来できるようにする。題は結論の文のまま (= 現在地は `kicker` が、言いたい
  ことは題が言う)。同じ小さい字が何枚も続いたら、その中の位置が書けていない。小さい字を題の左に並べる
  資料 (= `kicker = "beside"`) は幅が狭いので、番号と 1〜2 語に縮める
- **章・節・区分の名前は、その分野の通り名を使う** (= 自分で作った名前は、読み手が意味を訊き返す)
- **形は毎回同じ** ― 読み手が形に慣れると、中身の議論に時間が使える (= 次の回は `task round` で
  前の回から始める)

## 見た目

- **1 頁に図解を 1 つ以上** ― 実物の絵 / 数字から描くグラフ / 図形で組む概念図 のどれか。表と文章だけの
  頁は、見せる手間を省いたと受け取られる (= 道具は、図解の無い頁を組まない)
- **概念図と工程図は図形で組み、画像に文字を焼かない** ― 文字入りの絵にしてよいのは、データの描画と
  引用物だけ。素材の絵は文字なしで作り、名前は頁の文字で置く (= 人が PowerPoint で直せる)
- **画像の中の文字は、頁の上で 10pt 以上** (= 元の絵の大きさ × 頁の上の縮尺で数える)
- **本文は 12pt 以上、図の中の名前も 12pt が基準。10pt は出所と脚注だけ** ― 入らない時は文を削る
  (= 言いたいことは見出しに寄せ、本文は 1 行。細部は別の文書が持つ)。道具は縮めずに止まり、何が
  どれだけ足りないかを言う
- **文字の大きさは、資料の使い方で決める** ― 映すか、読ませるか (= `[theme] use`)。映す資料の途中に、
  読ませる 1 枚 (= 根拠の表、詳細の一覧) を挟む時は、その頁だけ使い方を変える (= 頁の `use`)。字を 1 つずつ
  小さくはしない
- **字の大きさと余白は、資料を通して 1 つの使い方で揃える**。紙 1 枚に詰める企画書の頁のような特殊な頁だけ、
  その頁の使い方を変える (= `use = "sheet"`)
- **図表は横長を保ち、余白を詰め、字を大きく**。実物の絵を大きくしすぎない (= 読み方と数字の場所が
  無くなる)
- **頁の主役を、地味な大きい表にしない** ― 主役は図。表が主役でよいのは早見表だけ
- **意味の無い要素は消す** ― 印・点線・区切り・注記は、題の証明に要る物だけ
- **色は意味を持たせ、使ったら凡例** ― 担当・状態・重要度のどれか 1 つ。同じ担当は全頁で同じ色・
  同じ並び (= `[theme.grounds]` に意味の名前で宣言すれば、凡例は自動で出る)。`good` / `bad` は
  読み (= 良い / 悪い) を示す物にだけ使う
- **目を集めるのは 1 つ** ― グラフの `highlight`、箱と棒の `strong = true`。全部を強調すると何も目立たない
- **空のセルを残さない** (= 値が無いなら「―」)
- **工程表** ― 縦にレーン (= 担当・仕事の線) を 4〜6 本、横に期間。期間の境は一目で分かること、棒の端は
  期間の境に揃えること (= 半月は本当に半月の時だけ)、棒の名前は棒の中に短く、到達点は全レーンを
  貫く線で数を絞ること、期間の性格 (= 動かせる / 期限が固い) は列の上の帯で 2〜3 区間まで

## 実物とデータ

- **数値は、結果の file から機械で埋める。手で打たない** (= グラフは `data = "x.csv"`、表も生成して渡す)
- **実物 > 概念図** ― 実測の絵と実データのグラフが、一番強い証拠。概念図は、実物が無い時の代役。
  近すぎて疑わしい時 (= 正解と見分けが付かない) は、差分の絵も並べて「別物であること」と「近さ」を
  同時に示す
- **比べる絵は、共通の枠で切る**
- **絵の file 名で、どう作った絵かが分かるようにする** (= どの条件のどの出力か。連番にしない)
- **大きさや数の諸元は、設定に書いた値ではなく、出来た物を測って書く**
- **条件の違う実行の結果を、1 本の資料に混ぜない**
- **出した資料は、作った時の条件のまま動かさない** ― 外の設定を直に見に行かせると、過去の回が後から化ける
  (= 素材は `assets/<回の名前>/` に写して持つ)
- **結果の値に追従していない図形を見張る** (= 数字を直したのに、図の中の言葉が前の値のまま)
- 論文の図表は、引用を頁に載せる

## 言い回しと事実

- **内部の語を出さない** ― file 名・実行の名前・道具の名前・エージェントの名前
- **未確認を残さない** (= 相手に出す資料に「要確認」「追って記入」を残さない)
- **既出の再掲を、発見と言わない**
- **前提にしてよいのは、確かめた事実だけ** (= 推測を前提にして次の頁を組まない)
- **論文の一部の機構を切り出して、別の用途に読み替えない。図の説明文だけを根拠にしない**
- **限定は正直に添える** (= 「入力に制約が無い時の上限」のような、読み方の注意)
- **語は、読み手の物を使う** (= 相手が使った語か、その分野の通り名)

## 運び方

- **資料の計画 (= 構成案) を先に確かめる** ― 1 枚だけ頼まれても、前後の論理と章立てに乗せる
- **過去の回の頁を複製して、差分だけ変える。作り直さない** (= `copy` / `import` / `task round`)
  - 変えるのは文言と、変わった箇所の色だけ。差分の色は、まだ意味を持っていない色から選ぶ
  - 輸入元は、今の中身に一番近い回を選ぶ (= 型の違う回から引くと、所見が頁に合わない)
  - 絵と本文の行数を突き合わせる (= 3 つの絵の頁に、4 つめの説明を残さない)
  - 同じ文字列が頁の中に 2 つ在る置換は、全箇所を指す (= 既定は 1 つめだけ)
- **頁を作る前に、過去の回の同じ役割の頁を焼いて見る**
- **焼いて 1 枚ずつ目で見てから報告する** ― 検査が通っても、読みやすいかどうかは検査では分からない。見る点 =
  崩れ / 文字の切れ・重なり・余白 / 大きさと配置の不揃い / 量の過不足 / 図表と文の対応 /
  1 枚で分かるか / 前後のつながり / 抽象的すぎないか
- **出す前に、頼んだ人に見せる**
- **人が触るのは PowerPoint、差分の取り込みはエージェント** (= `task review`)。焼いた deck を人が直して
  終わりにしない ― 次の build で消える
- **必須の頁の欠けは、目で探さず機械に出させる**
- **修復のダイアログの原因は、修復された file との差分でしか確定できない** (= 検証の道具も
  LibreOffice も見逃す)

## 何の頁を、どの型で組むか

型の名前とキーの書き方は `reference.md`。ここは「作りたい頁」から型を引く表。

| 作りたい頁 | 型 | 要点 |
|---|---|---|
| 章立て (= 章の頭ごとに 1 枚、今の章だけ強調) | `agenda` | `highlight` に章の番号。`highlight_tone` で地の色、`numbers = "circled"` で丸の数字 |
| 実物の絵 1 枚と読み方 | `figure` | 絵は縦横比を保つ。`caption` に読み方 |
| 絵を並べて比べる | `figures` | 2 つ以上を横に。名前は絵の下 |
| 行 × 列の実物の比較 (= 手法 × 条件) | `figure_grid` | 絵は先に、行ごとに共通の枠で切っておく。名前と数字は絵に焼かず、頁の文字で置く |
| 工程を左から右へ (= 替えた段だけ色) | `flow` | 段の中にノード。色は `tone`、段の下の 1 行は `settled` |
| 入力から出力への縦の流れと、横への分岐 | `flow` | `direction = "down"`。段のノードが 2 つ以上なら分岐、次が 1 つなら合流 |
| 到達点までの道のり | `roadmap` | 段は矢羽根。到達点は濃い地 |
| 工程表 (= 縦にレーン、横に期間) | `timeline` | `phases` が期間の性格、`milestones` が全レーンを貫く日付 |
| 数字を比べる・移り変わり・内訳・増減 | `chart` | `bar` / `column` / `line` / `stacked` / `waterfall`。絵で貼らない |
| 2 つの量の関係 (= 2 軸に点) | `chart` | `kind = "scatter"`。軸の名前 `x` `y` は必須。系列の名前は凡例に出る |
| 手法・案・声を札で並べる | `cards` | 色は `tone`、絵は `icon`、列の数は `card_columns` |
| 早見表・権利の表・受け取った物の一覧・質問の一覧 | `board` | 表が主役でよい唯一の型。状態は `{ harvey }` / `{ mark }` |
| 値の大小を地の濃さで見せる表 | `board` | セルに `{ text = "…", shade = 0〜4 }`。段を決めるのは書く人 |
| 従来とこの手法を左右に、図と読み方を添える | `compose` | 段とマスで書く。マスに札・絵・表・グラフ・型を置ける |
| 制約から勧める案までを 1 枚に | `compose` | 型に合わせて話を曲げない。組めなければ、型を足す依頼にする |

- **中身が揃う前の頁**は、型ではなく札で言う ― `sticker = "暫定"` (= 何が入るかだけを書いた頁を、
  出来た頁と同じ顔で出さない)
- **表紙**は、テンプレートの頁を `copy` して文言を差し替える
