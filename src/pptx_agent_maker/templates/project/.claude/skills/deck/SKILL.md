# Building a deck

**ツールは `pptx-agent-maker`、案件はその外の folder。**案件を見つける口は `workspace.toml` 1 枚で、
それ以外に外の path を書かない。

案件の folder の中だけで完結する (= `Taskfile.yml` がツールへの口を持つ)。

**頁を設計する前に `craft.md` を読む** (= 何をどの順で言うか、何を載せないか、どの頁をどの型で組むか。
型と検査が守れるのは座標と形までで、そこから先は書く人が決める)。

## 作る順番 (= 1 つも飛ばさない)

⚠ **差し戻しで一番多いのは、作法の 1 つを外したことではなく、この順番の段を飛ばしたこと。**急いでいる時と、
指摘を受けた直後ほど飛ばす。頁 1 枚を直すだけの頼みでも、1 (= 材料)・2 (= 同じ資料の頁を見本に)・8 (= 全頁を
見る)・10 (= 辻褄) は踏む。

0. **ツールを更新したら `task refresh`** ― この folder の task の口と手順書 (= このファイル) は `init` の
   時点の物。新しい口は配り直すまで届かない (= 案件の file には触らない)
1. **材料を最後まで読む** ― 計画書・報告書・引き継ぎの資料・前の回の資料と manifest (= 頁ごとの `why` に、
   前に決めた方針が在る)・案件の説明のページ・前の会話で決めた事。途中で止めて組み始めない
   (= 全体を掴まずに組んだ頁は、章の筋から外れ、前に決めた事を落とす)。`task show` が案件の置き場を出す
2. **見本を絵で見る** ― 場面の近い良い資料を 2〜3 本と、前の回の同じ役割の頁を、焼いて目で見る。
   場面は題材でなく使われ方 (= 毎週の報告・提案・打ち合わせ) で選ぶ。見本の集まりの置き場は `craft.md` の「運び方」
3. **目次と章立てを決める** ― 資料の頭に目次を置き、章とその中の段を先に決める。報告書から組むなら、章の順は
   報告書に揃え、報告書の表と図の全量を資料のどこに置くかの一覧を作る。会の種類 (= 報告・提案・打ち合わせ) で
   骨格が変わる (= `craft.md` の「構成」)
4. **頁ごとに「何を言う頁か」を 1 行で決める** ― 題か結論の帯にそのまま書ける文で決め、ほかの頁と同じ事を
   言っていないかを見る。決めた 1 行は頁の `why` に書く (= 次に触る人と次の回が読む)
5. **材料を作る** ― 頁ごとの数の表と絵を道具で作る (= 数は結果の file から機械で、絵は `task frames -- w1` の
   枠の大きさで)。頁は材料から組む
6. **構成案を出して、合意してから組む** ― 頁の並び・各頁の 1 行・変える所と文言を一覧にして、頼んだ人に
   チャットで出す (= 量と並びが要る時は、仮に組んだ絵も添える)。「はい」をもらってから焼く。1 頁直して見せ、
   また 1 頁直す往復にしない
7. **manifest を書いて組む** ― 並びの真値はここ 1 枚。頁の作り方は 3 つ (`copy` / `import` / `declare`) と、
   案件の recipe を呼ぶ `recipe`
   - **同じ役割の頁が過去の回に在れば、複製するか輸入する** (= 作り直さない)。中身だけ新しくするなら
     `pictures` / `tables` で入れ替える ― 並び順は `task show -- w1.pptx:12` が出す。数や表の形が合わなければ
     build が止まる
   - **次の回は前の回から始める** ― `task round -- w2 --from w1` (= manifest を複製し、出力の名前と素材の
     置き場を新しい回へ。素材は写らないので、この回の絵を `assets/<回の名前>/` に置く)
   - `task build -- w1` が組んで検査まで行う。組めたら `task titles -- w1` で題だけを順に読み、話が通るかを見る
8. **焼いて、全頁を 1 枚ずつ目で見る** ― 文字で確かめて済ませない。⚠ **検査が通っても、読みやすさは座標に
   出ない。**見る点 = 重なり・はみ出し・空き・量・同じ資料のほかの頁と作りが揃っているか (= `craft.md` の
   「運び方」に全部)。道具の不具合で崩れた頁は、直るのを待たずに崩れない組み方へ替えてから見せる
9. **締めの頁を作る** ― 会議の資料は「今日決めたいこと」と「まとめ」、提案は相手へのお願い、報告は問いへの答え
   で締める
10. **全頁の辻褄を洗う** ― 頁を足し引きしたら、頁番号・章番号・目次・呼び名・数字・人が直した結論が、全頁で
    合っているかを見る。頁の数字と断定は結果の表と突き合わせ、前の回の課題の一覧と今回の頁も突き合わせる
11. **人が見ている画面に、組んだ版が出たかを確かめる** ― 人はデッキを、機械に常駐しているプレビュー
    (= `pptx-agent-maker preview` を OS の service で走らせた物) で見る。⚠ **自分で焼いた絵を見て
    済ませない。**その画面の欄にこの案件が出ていて、組んだ版が映っていることまで確かめる:

    ```bash
    curl -s localhost:<port>/api/projects           # 欄の名前。読めない案件は problems に理由が付く
    curl -s 'localhost:<port>/api/decks?p=<名前>'    # 各デッキの last_rendered_at が build より後か
    ```

    `<port>` は常駐の service 定義が渡している `--port` (= macOS なら `launchctl list` で名前を引き、
    その plist を読む)。欄に無い・名前に ⚠ が付いている時は `problems` の理由を読む ―
    「restart the preview」と出ていれば、常駐が起動した時の古い道具のまま走っていて、この案件の
    `workspace.toml` を読めない。常駐を起動し直す。常駐の無い機械では `task preview` で開いて見せる。
    人と頁の話をする時は、人が見ているその画面の頁の番号で言う
12. **会議の前に PDF に書き出す** ― PowerPoint で書き出し、資料の隣に置く (= 映す機械で開けない時の控え。
    LibreOffice は書体が無いと別の書体に置き換え、折り返しが PowerPoint と変わるので、渡す PDF には使わない)
13. **人が PowerPoint で直したら取り込む** ― `task review -- w1.pptx --apply`。**取り込みはエージェントの
    仕事で、人に残さない。**文言は宣言か `replace` へ、絵は `assets/` と `pictures` へ、それ以外
    (= 位置・大きさ・書式・新しい場所の文字・足した頁) はその頁を人が直した版からの `import` にする。
    焼き直して直した版と同じに読めることを確かめてから書く (= 違えば何も書かずに止まる)
14. **同じ形を 2 回書いたら上げる** ― `task promote -- <名前> w1:5 w2:7`。
    ⚠ **3 回目を複製で書かない。**前の世代は上げずに複製し続け、同じ頁の手書きが溜まった

## 同じ形の頁は recipe にする

毎回同じ形で組む頁 (= 毎週の結果頁など) は、`recipes.toml` に決まった部分を 1 回だけ書き、
manifest の頁は**変わる部分だけ**を渡す。上げるのは `promote` 1 回 ― 全部で同じ値のキーが
recipe になり、違うキーが各頁に残り、元の頁は recipe を呼ぶ形に書き換わる。書き換えた後の頁が
元と 1 つでも違えば、1 file も書かずに止まる。

```toml
[[pages]]
kind = "recipe"
recipe = "result"
fill = { method = "手法 A" }     # recipe の文言の {method} を埋める
figures = [["a.png", "正面"], ["b.png", "背面"]]
```

## 同じ形のマスは部品にする

`compose` の 1 マスで何度も書く形 (= 大きな数字とその意味、発言、名前付きの絵) は、`recipes.toml` に
`[parts.<名前>]` で 1 回だけ書き、マスで `part` と `fill` で呼ぶ。決まりは頁の recipe と同じ ― マスは部品が
決めたキーを書き換えられず、穴は埋め残せない。マスが自分で持つのは置き方 (= `weight` と `id`) と、部品が
決めていないキー (= 絵ごとに違う `marks` など) だけ。部品は部品を呼べる (= 自分を呼ぶ部品は止まる)。

```toml
# recipes.toml
[parts.big_number]
rows = [ { cells = [ { text = "{figure}", role = "display" } ] },
         { cells = [ { text = "{meaning}" } ] } ]

# 頁のマス
[[pages.rows.cells]]
part = "big_number"
fill = { figure = "98%", meaning = "15 歳の 98% がスマートフォンを持つ" }
```

- **新しい案件は見本の部品を 9 つ持って始まる** (= `big_number` `quote` `named_picture` `tree` `cycle` `code`
  `overlap` `map` `equation`)。案件に合わせて書き換え、使わない物は消してよい。今ある部品は `task types` が出す
- ⚠ **形が足りない時は、道具への依頼の前に部品を 1 つ書く** ― `compose` の素 (= カード・文章の役・絵・表・
  グラフ) と並べ方 (= 段とマス・輪・木・重なり・絵の上の印・マスどうしの線) で組めるなら、それは案件の部品。
  道具への依頼にするのは、素か並べ方そのものが無い時だけ

## 別の案件でも使う物は、会社のテンプレートへ上げる

案件の中の recipe とは粒度が違う ― 上げた物は**次の案件すべてに配られる**。上げるかどうかは
人が決める (= エージェントは候補を挙げるまで)。

```bash
task lift -- <テンプレートの folder> --page w1.pptx:3 --keep "項目" --replace "手法 A=<手法名>"
task lift -- <テンプレートの folder> --part big_number         # 部品 (= recipe も --recipe で同じ)
```

- **部品と recipe は、文言だけが仮の語になる** ― 選ぶ値 (= `type` `role` `tone` `kind` `direction` など) と、
  穴だけの値 (= `{figure}`) はそのまま上がる

- **文言は既定で全部抜ける** ― 表の値も含め `<文言 1>` `<文言 2>` … の仮の語になる (= 同じ文言は
  同じ番号)。残るのは `--keep` で指した語 (= 章や表の見出し) と、`--replace` が当たった文言だけ。
  指し忘れた語は抜ける側に倒れる
- **絵は灰色の仮の絵、代替テキストは消える** (= 絵も案件の中身)
- 頁はテンプレートの末尾に足され、次の案件は `copy` で呼んで `replace` / `pictures` / `tables` で埋める。
  仮の語の頭と置き換え先の語は `stale_words` に入り、埋め忘れは検査が止める
- 1 度も当たらない `--replace` は止まり、何も書かない
- 上げた後に「何が何になったか」が全部出る ― **残すべき語が仮の語になっていないか読み、要れば
  `--keep` を足して上げ直す** (= 上げる前のテンプレートは `_archive/<時刻>/` に控えがあり (= 新しい方から 3 世代)、
  その file を戻してから上げ直す)

⚠ **頁は recipe が決めたキーを書き換えられない** (= 書き換えると同じ recipe の頁が回ごとに
ずれる)。違う形が要るなら recipe を直すか、別の recipe を上げる。題の一部だけ違う場合、
`promote` は題ごと頁に残す ― `{method}` のような穴を空けて recipe へ寄せるのは人が決める。

## 宣言で頁を組む

**型を選ぶ。**`figure` / `figures` / `figure_grid` / `flow` / `roadmap` / `timeline` / `chart` / `cards` / `board` / `agenda` の 10 個。
**数字を見せる頁は `chart`** (= 数字から描くグラフ。絵で貼ると、渡した先で誰も数字を直せない)。
⚠ **どの型にも合わない組み方は `compose` で段とマスに書く** (= 型に合わせて指定を曲げない。目標を 1 枚に、
と言われたら 1 枚で組む)。`compose` でも組めない物 (= 素か並べ方そのものが無い) だけを、道具への依頼にする
(= 組める形を何度も書くなら部品にする。上の「同じ形のマスは部品にする」)。
型ごとに読むキーと案件の recipe は `task types` が出す (= コードの登録から出るので、ここより正しい)。
⚠ **座標を書く口はどこにも無い。**頁の並びは固定で、書いた帯だけが出る:

```
題 → 条件の帯 → カード → 本体 → 表 → 読み方 → 結論の帯 → 出所
```

型が決めるのは**本体**だけで、カード・表・読み方・要点は**どの型にも**添えられる
(= キャプションは絵の型だけ。型ごとに読むキーは `reference.md`、作りたい頁から型を引く表は `craft.md`)。

```toml
[[pages]]
kind = "declare"
type = "figure"
title = "この頁が何の頁か"
figure = "a.png"          # assets/<この manifest の名前>/ から引く
caption = "図の読み方を 1 行"
conclusion = "持ち帰ってほしい 1 行"
```

## 型に収まらない頁が出たら

**型を足す。**手で図形を置く道は無い (= その口を塞いだのが、このツールの設計そのもの)。
手順 = ツールの repo の `docs/reference/adding-a-type.ja.md`
(= https://github.com/Synforger/pptx-agent-maker/blob/main/docs/reference/adding-a-type.ja.md)。⚠ **足す前に、付属で足りないかを見る**
(= カード・表・読み方・要点で済むことが多い)。

## 見た目

**`specimen.pptx` 1 枚が持つ。**複製した頁も、型で組んだ頁も、PowerPoint で手で足した頁も
そこから取る。`workspace.toml` の `[theme]` はその上に重ねる例外 (= 書いた色だけ上書き)。

**文字の大きさは資料の使い方が決める** ― `[theme] use = "present"` (= 映して話す資料) で全部が大きくなり、
載る量は減る。書かなければ `"read"` (= 手元で読ませる資料)。役ごとの上書きは `[theme.type]` (= reference)。
**資料ごと・頁ごとにも選べる** ― 映す資料の途中に情報を詰めた 1 枚を挟むなら、その頁に `use = "read"` と書く
(= 付録や詳細の資料なら、その manifest の先頭に)。頁に書けるのは使い方の名前だけで、大きさは `workspace.toml` が持つ。
**紙 1 枚で読ませる頁は `use = "sheet"`** (= 字が小さく、余白と間隔も同じ比で詰まる。企画書の 1 枚)。
**基本は案件の使い方 1 つで通す** ― 別の使い方 (= `sheet` や、案件が名前を付けた使い方) を選ぶのは、特殊な頁や
デザインを書く時だけ。下限と余白を案件で動かす書き方は reference の「案件の使い方に名前を付けて足す」。

## 組めないもの (= 直そうとせず、形を変える)

| 拒まれるもの | なぜ |
|---|---|
| 図解を 1 つも持たない頁 | 表と文章だけの頁は、読み手が使えない (= `cards` / `board` / `agenda` は骨格なので例外) |
| 表の空セル | 値が無いなら「―」。空欄は埋め忘れと見分けが付かない |
| 下限を割る文字 (= 読ませる資料は 10pt、映す資料は 14pt) | 席から読めない |
| 枠に入らない表 | PowerPoint は表を縮めず枠を伸ばす。頁から溢れる |
| 知らないキー | 綴り違いを捨てると、書いたつもりで頁には無い |
| 手編集された deck への上書き | 人の直しは退避してから、`review` で取り込む |

## やらないこと

- **寸法・色・文字を頁が決めない** ― 同じ役割が毎回同じ形で出ることが、回をまたいだ比較の前提
- **案件のものをツール側に置かない** ― 並べ方・素材・見た目は案件のもの。ツールが持つのは型まで
- **1 往復 1 修正を繰り返さない** ― 焼く前に、その頁の文言と中身を決め切る
