# 型を足す

前の世代では、よく使う頁の形を**案件のプロジェクトからプロジェクトテンプレートへ昇格させ、そこから各案件へ配って
いた**。その口は動かないまま、同じ部品が案件ごとに複製されて増えた。

この世代では、**頁の形はツールのコードに在る**。だから足す先はプロジェクトテンプレートではなくツールで、足した瞬間に
全案件が使える ― **配って回る工程そのものが無い。**

## いつ足すか

**型に収まらない頁が出たとき。**それ以外の入口は無い (= 座標を受け取る口も、案件ごとの頁
script も塞いである)。「今回だけ」の形を手で置く道が無いので、**足すか、既存の型で組むかの
二択**になる。

⚠ **付属で足りないかを先に見る。**カード・表・読み方・結論の帯・出所はどの型にも添えられる。
実物で数えたときは、**型の数を増やす方向に 2 度間違えた** ― 付属の有無で型を分けていて、
8 → 12 → 7 と切り直した。

## 足し方

1. **`src/pptx_agent_maker/layout/types.py` に 1 つ書く。**

   ```python
   @register("board", needs=["table"], figure=False)
   def _board(page: Page, spec: Spec, area: Rect) -> None:
       ...
   ```

   `needs` = その型が無いと成立しないキー。`takes` = **この型だけが読む任意のキー**
   (= `figure` の `caption` / `figure_grid` の `columns`)。`figure=False` は図を持たなくて
   よい型 (= 頁の骨格。既定では図解を 1 つも持たない頁は組めない)。

   ⚠ **読むキーは全部宣言する。**宣言し忘れたキーは拒まれるので書いた人がすぐ気づくが、
   逆に「どの型でも書ける」ことにすると、読まない型では黙って落ちる (= 実際に `figures` の
   頁で `caption` が落ちていた)。

2. **本体は `area` を割るだけで書く。**`Page` のメソッド (= `figure` / `table` / `cards` /
   `note` / `points`) を通す。⚠ **生の寸法を書くと test が赤くなる** ― 寸法は
   `src/pptx_agent_maker/layout/tokens.py` の 1 枚が持つ。

3. **`tests/test_types.py` は自動で拾う。**全型を総当たりする test が在るので、書いた時点で
   「枠から出ない」「付属が全部付く」「並びが変わらない」が掛かる。

4. **焼いて画像で見る。**test が緑でも、文字の折り返しで壊れる欠陥はそこでしか出ない
   (= 実物を焼いて初めて出た欠陥が続いた)。

## 足した後

何もしない。案件は次の `build` からその型を使える。⚠ **案件側の file を触る必要は無い**
(= `workspace.toml` にも `specimen.pptx` にも型の情報は入っていない)。

型を使うのは manifest の 1 行だけ:

```toml
[[pages]]
kind = "declare"
type = "board"
```

## 昇格しないもの

- **見た目** (= 書体と色) ― 案件のもの。`[theme]` と `specimen.pptx` が持つ
- **並べ方** ― 案件のもの。manifest が持つ
- **その回だけの絵** ― 案件のもの。`assets/<回>/` が持つ
